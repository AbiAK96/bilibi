## Shared UI primitives

- Use the macros in `templates/components.html` (`{% import "components.html" as ui %}`) for page, header, section heading, card, facts, stat strip, button, icon button, create button, back link, action link, badge and icon, not hand-written markup: that file is the one DOM source, mirroring Bilimbi `apps/base/ui/lib/ui/components.ex` at the pinned snapshot, so a screen that copies classes drifts from parity the next time the shared file changes. A crate outside `base/ui` reaches the same macros through the typed models in `src/components.rs` (`Button`, `Card`, `Facts`, ...), which render through the same macros.
- Name variants through the enums in `src/components.rs` (`ButtonVariant`, `BadgeKind`, `IconContext`, `IconKind`, `Chrome`, `PageVariant`, `StatKind`), not class strings; the class decisions live in their methods and in `card_flat`, `card_pads` and `stat_strip_columns`.
- Pass secondary slots (`actions`, `title_actions`) as an `Html` fragment rendered by another component, and keep `|safe` inside the shared macros only; see `src/html.rs`. Request data goes through `Html::text` or a template, never `Html::raw`.
- Askama refuses a macro nested in its own body, so a card inside a card renders the inner one through the typed `Card` model; `card_flat`/`card_pads` resolve the `p-0` and padding conventions, so do not append padding classes expecting the default to win.
- Name icons through `src/icons.rs` action names (`"edit"`, `"manage"`) or `hero-*`; an unregistered name panics on purpose, and names from stored data pass `icons::renderable` first.
- Use the macros in `templates/forms.html` (`{% import "forms.html" as form %}`) for every form control (input of any type, select, textarea, checkbox, password with reveal, secret and stored-secret input, code input, combobox, multi-select, radio group, restricted value and restricted field), not hand-written `<input>` markup: that file mirrors Bilimbi `apps/base/ui/lib/ui/components/forms.ex`, and each macro takes one typed model from `src/forms.rs` (`Field`, `SecretInput`, `CodeInput`, `Combobox`, `MultiSelect`, `RadioGroup`, `Restricted`, `RestrictedField`) built with its chained setters. Field classes, described-by wiring, invalid state and the keep-current mask are decided in those models, so a page passes errors, hints and `readonly`/`disabled` and never composes control classes itself; a stored secret passes `stored()` and the model discards the value.
- The form controls' browser halves live in `assets/hooks.js` (served at `/assets/hooks.js`, loaded after `ui.js`): CodeInput, Combobox, SecretReveal, SecretClear, SecretStored and DisclosureDismiss register with `BilibiUI.registerHook` and report with `this.emit`; a server push (the owner's `LiveBody.events`) reaches a hook as a `window` event `bilibi:<name>` (`bilibi:secret:reveal` carries `{id, value, duration_ms}`). A control that reports to the server carries `data-event` (plus `data-name`/`data-option`/`data-key`), the counterpart of Bilimbi's `phx-click`; never bind listeners to a control's parts from a page.
- Edit a record's facts in place with `templates/inline.html` through the typed `InlineEdit`, `InlineLongText` and `InlineChoice` (`src/inline.rs`; browser half `assets/inline.js`, served inside `/assets/hooks.js`), not an Edit button, `/:id/edit` route or page-owned form: they own Saving…, draft recovery and version carry-back. Record outcomes with `CommitStates`/`CommitStatus` (`refusal`, `failure`); a refused or forbidden write must not return `Error::Forbidden`/`Error::Internal`, which the live transport treats as fatal and clears the page. `docs/inline-editing.md` is the owner contract.
- `/assets/ui-components.html` (`src/specimen.rs`) is the screenshot baseline for every primitive and variant; extend it when a primitive or variant is added, and keep its content mirrored in the Bilimbi reference renderer kept with the task evidence, not in this repo. Add to a section under `templates/ui_components_specimen/` (a new one goes in the `sections!` list), keeping each to a few heavy form controls, never into one page-sized template: askama inlines every macro call into one function, and the whole page as one made this crate's `rustc`/`clippy-driver` peak at 9 GB (`src/section.rs`).

## Feedback, dialogs and tabs

- Use `templates/feedback.html` (flash, `flash_group`, `connection_banners`, `alert`, `panel_notice`), `templates/dialog.html` (`modal`, `confirm_dialog`) and `templates/tabs.html` (`tabs`), or their typed models in `src/feedback.rs`, not hand-written `<dialog>`, banner or tab markup: the DOM mirrors Bilimbi `components.ex`, and `assets/css/app.css` selectors (`body:has(dialog:modal[data-owns-flash])`, the `#connection-*` ids) depend on it.
- Never use `window.confirm` or a `data-confirm` attribute; an irreversible action renders `ConfirmDialog` while its request is pending and stops rendering it whatever the outcome. The server owns whether a dialog exists, so Escape and Cancel only raise the cancel event.
- Browser behaviour is `assets/ui.js`: a component names its controller with `data-hook`, and a controller reports intent with a bubbling `bilibi:event` CustomEvent (`detail.event` plus values), which the transport turns into a server event. The transport reports the socket with `bilibi:disconnected` (`detail.kind` `client`/`server`) and `bilibi:connected` on `window`; new controllers register with `BilibiUI.registerHook`. Do not ship Phoenix hooks (`pushEvent`, `mounted`-only lifecycles) unchanged.
- Pick a message kind by what it does: a completed write is `Success` (times out), a refusal or failure is `Error`, `Info` informs without confirming a write; only success carries auto-dismiss.
- `/assets/ui-feedback.html` (`src/feedback_specimen.rs`) is the screenshot baseline for these; its `static/ui-feedback-demo.js` stands in for the server, so extend both when adding a variant, in a section under `templates/ui_feedback_specimen/` as above.

## Shell (`templates/shell.html`, `framed.html`, `assets/shell.js`)

- Pages never render chrome: the host wraps every discovered page through `apps/web/src/shell.rs`, which builds `ShellContext` (`src/shell.rs`) from the sealed scope (menu via effective capabilities, operator standing via `tenancy::prove_operator`). Core contributes into the `notifications` slot through the `shell.notifications` embed, which Web renders and mounts as a shell panel; Base UI never imports Core.
- A hook's `apply()`/`updated()` must write the DOM only on change: `ui.js` reports any child-list mutation inside a hooked element as `updated`, so an unconditional `replaceChildren` or `textContent` write there loops forever and hangs the tab (see `renderPinnedItems` in `assets/shell.js`).
- Theme, time-display mode and pins belong to the signed-in account (`bilibi_user::presentation`, `list_pins`, saved through `/preferences` and `/api/pins`); the shell renders them into `data-theme-choice`, `data-display-mode` and `data-pins`. Do not keep them in `localStorage`, which differs per device and per account on one browser.

## Live pages (`assets/live.js`)

- Raise intent with `data-event` (or a `bilibi:event`) and let the transport queue it: never keep a "pending" flag or drop input while a round trip is in flight. Every intent is sent in order with a `request_id` the server echoes; `docs/live-pages.md` is the contract. Use `data-working` for a busy label; the transport adds and lifts `aria-busy` itself.
- Give a stable `id` to any repeated fragment that holds a draft, a hook or an `<iframe>` (Company's inline forms are `company-field-<key>`): a reply is patched by element id, and unkeyed siblings match by position, so a removed earlier sibling would otherwise hand a draft to the wrong form. Never rebuild `#app` or a panel with `innerHTML` from a page or hook; an iframe reloads whenever it is moved or replaced.
- Mark a subtree the browser owns (a hook-filled status, a frame host's own text) `data-live-ignore`, the counterpart of Bilimbi's `phx-update="ignore"`: only its `data-*` attributes then follow the server. Do not fight the patcher from `updated()`; on an existing element it leaves `<details>`/`<dialog>` `open` and an iframe's `src` alone, and the browser's own dirty flags keep typed values, except in a `data-change` form, whose controls follow the server unless focused.

## Operational lists

- Build a list page from `ListState` (`src/list_state.rs`: one validated `ListSpec`, `parse` on load/mount/params, `apply_filters`/`next_sort`/`put_page` on events, `to_params()` as `LiveBody.query`) and the macros in `templates/lists.html` through their models in `src/lists.rs` (`FilterToolbar`, `Table`, `Pagination`, `EmptyState`), not hand-parsed query strings or table markup: the spec bounds every untrusted value and the URL it returns is what Back and reload restore. Keep a module's existing query names and page sizes in its spec. `apps/web/examples/list-reference.rs` is the running specimen.
